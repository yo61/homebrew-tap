## Decision: Pin `brew pr-pull` to `workflow_run.head_sha` in `publish-bottles.yaml`

Pass `--head-sha="$HEAD_SHA"` (from `github.event.workflow_run.head_sha`) to the
`brew pr-pull` invocation that lands green bump PRs on `main`.

## Context: {why this came up}

`publish-bottles.yaml` diverges from Homebrew's stock `publish.yml` (generated by
`brew tap-new`): the stock workflow is manual (`workflow_dispatch`, a maintainer
supplies the reviewed PR/sha), ours is automatic (`workflow_run` on a green
`brew test-bot` run, guarded to same-repo `bump/*` branches). Reviewing the
implementation against the official tap-maintenance docs and the `tap-new`
templates surfaced that both pass `--head-sha` to `pr-pull` "to prevent
publishing different commits than reviewed", and our workflow did not.

In the automatic flow this is a TOCTOU gap, not just a nicety: test-bot goes
green on `workflow_run.head_sha` and builds bottles for that commit, but this job
resolves the PR by head *branch* (`gh pr list --head "$HEAD_BRANCH"`) and pulls
whatever is currently at the PR head. If the branch head moves between the green
run and pr-pull firing, untested code could be landed on `main` by the
`always`-bypass App. The tested sha is already available for free in the
`workflow_run` trigger context.

## Alternatives considered:

- **Leave it off (status quo).** Rejected: real TOCTOU window in the automatic
  flow; diverges from Homebrew's documented guidance for no benefit.
- **Switch to the stock manual `workflow_dispatch` publish flow.** Rejected:
  defeats the feature's purpose (auto-publish bottles on green bump PRs).
- **Add `--head-sha` (chosen).** Keeps the automation, closes the gap, realigns
  with the canonical template and docs.

## Reasoning:

One-line change, no new dependencies or permissions, directly implements the
security recommendation from Homebrew's own docs and template. `pr-pull` refuses
to publish if the PR head no longer matches the tested sha.

## Trade-offs accepted:

If a bump branch is force-updated after going green (not expected — only the
`SEMANTIC_RELEASE_APP` writes these branches), pr-pull will now fail closed
rather than publish. That is the intended behaviour: a failed publish leaves
`main` untouched and the PR open for re-run.
